# フロントエンド仕様

> **ステータス：確定**（自社ロゴの扱いのみ保留。8章参照）

## 1. 利用状況から導かれる設計原則

**営業担当のノートPCを卓上で顧客に見せる。** 画面から目までの距離60〜80cm、顧客は斜めから見る。この前提から次が決まる。

| 原則 | 理由 |
|---|---|
| 文字を大きく、情報密度を低く | 一般的な14pxは斜めから読めない |
| 淡い色を使わない | ノートPCは角度で色が飛ぶ。薄いグレーの補足文字は正面の営業にしか見えない |
| 色分けは文字色ではなく背景の塗りで表現 | 同上 |
| ダークモード非対応 | 明るい背景の方が視認性が高く、PDF出力とも整合する |
| タブ分割をしない。縦1本のスクロール | 情報を隠すと「あの数字どこでしたっけ」で商談のテンポが崩れる |

## 2. 技術方針

| 項目 | 決定 |
|---|---|
| 実装方式 | Jinja2 テンプレート＋素のJavaScript |
| ビルド工程 | なし（React・Vue・バンドラを導入しない） |
| CSS | 単一ファイル。フレームワーク不使用 |
| 対応ブラウザ | Chrome / Edge / Safari 最新版 |
| 主対象画面幅 | 1280px以上。1024pxでも崩れないこと |
| コンテンツ最大幅 | 1080px。中央寄せ |
| レンダリング系統 | 画面とPDFで同一。Jinja2とJSの二重実装をしない |

## 3. 配色

紺を面（帯・バーの塗り）に、金を**総合スコアの目盛りマーカー1点のみ**に使う。「金が指している場所＝いま見るべき数字」という約束を守り、金を他所に散らさない。

```css
--navy-900: #12243A;  /* ヘッダー帯 */
--navy-700: #1D3A5C;  /* 見出し・強調 */
--navy-500: #2F5B8C;  /* スコアバーの塗り */
--navy-100: #E3EAF2;  /* 淡い帯・行の交互背景 */
--gold:     #C08A1E;  /* 目盛りマーカー・セクション見出しの罫 */
--gold-100: #F2E6C8;  /* 合計行など、ごく限定的に */
--ink:      #14202E;  /* 本文 */
--ink-sub:  #47586B;  /* 補足。これより薄い文字色を作らない */
--line:     #C7D2DF;  /* 罫線 */
--paper:    #FFFFFF;
--mist:     #F2F5F8;  /* カード背景 */
```

**評価バンドの色**（`docs/scoring.md` のgood/fair/weak/poorに対応）

```css
--band-good: #2E7D5B;
--band-fair: #C08A1E;
--band-weak: #C2703A;
--band-poor: #B3453C;
```

バンド色を使ってよいのは次の2箇所のみ。

- 総合スコアの脇に置く小さなバッジ
- 「最初に着手すべき3項目」の左端の縦罫

**カテゴリ別スコアのバーは、点数にかかわらず全て `--navy-500` で塗る。** 低いカテゴリを赤くすると商談の場で攻撃的に見える。長さの差だけで十分伝わる。

## 4. 書体・サイズ

```css
--font: "Zen Kaku Gothic New", "Hiragino Kaku Gothic ProN", "Yu Gothic", sans-serif;
```

Google Fonts から 400 / 700 の2ウェイトのみ読み込む。数値は同じ書体に `font-variant-numeric: tabular-nums` を当てて桁を揃える。別書体を混ぜない。

| 用途 | サイズ | ウェイト |
|---|---|---|
| 総合スコアの数値 | 56px | 500 |
| セクション見出し | 20px | 700 |
| カテゴリ名・表の本文 | 16px | 400 |
| 営業トーク要約 | 17px / line-height 1.8 | 400 |
| カテゴリスコアの数値 | 20px | 500 |
| 補足・単位 | 14px | 400 |
| 最小サイズ | 13px | — |

13px未満を使わない。

## 5. 画面構成

### 5.1 診断入力

1画面完結。URL入力欄（高さ56px・font-size 18px）＋デバイス選択（PC／スマホ／両方のラジオ）＋診断ボタンのみ。それ以外の要素を置かない。

### 5.2 進捗表示

診断開始後、入力欄は上部の細いバーに収納する。

**7工程を縦リストで表示する。** 横一列だとラベルが入りきらず、完了した工程の実測値を添えられない。

```
✓ サイトを読み込み中          1,240文字を取得
✓ 対策キーワードを推定中       8件を推定
● 検索順位とAI Overviewを取得中
○ 表示速度を計測中
○ 競合サイトを分析中
○ 被リンクを調査中
○ スコア算出・要約生成
```

- 完了した工程には実測値を右に添える
- 実行中の工程のみアニメーションを付ける
- 失敗した工程は警告アイコン＋理由を表示し、処理は続行する
- 残り時間のカウントダウンは出さない（PageSpeedの所要時間が読めず、外れると不信を招く）

### 5.3 診断結果

縦1本のスクロール。順序は固定。

```
┌─ ヘッダー帯（--navy-900） ────────────────────┐
│ example.co.jp    トップページの診断結果 ・ 日付 │
├───────────────────────────────────────────────┤
│ ┌ 総合スコア ─┐ ┌ 営業トーク要約 ──────────┐ │  ← ここまでが第1画面
│ │    62       │ │ 4〜5文                    │ │
│ │  ▁▁▁▁▲▁▁    │ │                          │ │
│ └─────────────┘ └──────────────────────────┘ │
├───────────────────────────────────────────────┤
│ カテゴリ別スコア（4行・内訳は折りたたみ）      │
│ 最初に着手すべき3項目                          │
│ 検索順位とAI Overview（キーワード別の表）      │
│ 競合3社との比較                                │
│ 警告（取得に失敗した項目があれば）             │
└───────────────────────────────────────────────┘
```

**スクロールなしで見える範囲に、総合スコアと営業トーク要約だけを置く。** ここだけで会話が始められる状態にする。顧客の視線は数字に、営業の視線は要約に向かうため、同じ行に左右で並べる。

### 5.4 総合スコアの表現

**円形ゲージ（ドーナツ型）を使わない。横方向の目盛り付きバーとする。**

- 斜めから見たとき、円形は歪むが横バーは歪まない
- 4カテゴリを縦に並べたとき、長さで直感的に比較できる
- 「計測器」の見た目になり、実測値だという印象を与えられる

構成：数値56px＋「/ 100」＋高さ10pxのトラック＋現在値の位置に金のマーカー（幅3px・高さ20px）＋下に 0 / 40 / 60 / 80 / 100 の目盛りラベル。

### 5.5 カテゴリ別スコア

1カテゴリ＝1行。左からカテゴリ名（固定幅）／バー（可変幅）／数値（右揃え）／開閉アイコン。

**内訳は既定で折りたたむ。** 開くと各項目を「項目名 ─ 実測値・獲得点/配点」の形で表示する。

```
本文の情報量            約1,240文字 ・ 15/30
キーワード網羅性        8件中5件が出現 ・ 16/25
タイトル・見出し構造    H2が3個 ・ 17/25
```

実測値と配点を必ずセットで出す。商談中に「その点数の根拠は？」と聞かれたときの答えがここになる。

未計測カテゴリ（被リンクAPI失敗時など）は、バーを灰色の斜線パターンにし、数値の代わりに「未計測」と表示する。

### 5.6 検索順位の表

| キーワード | PC | スマホ | AI Overview |
|---|---|---|---|

- 圏外は「20位圏外」と表示する（空欄にしない）
- AI Overview 列は「表示なし」「表示あり」「表示あり・引用されている」の3状態
- 引用されている場合のみ、その行に淡い紺の背景を敷く
- デバイス選択で片方のみを選んだ場合、該当列を出さない

### 5.7 競合比較

自社を最上段に固定し、その下に競合3社を並べる。指標は列方向。自社の行に淡い紺の背景を敷いて位置を見失わせない。

数値差分の解説文（Claude生成）は表の下に配置する。

### 5.8 警告表示

取得に失敗した項目がある場合、結果の末尾ではなく**ヘッダー直下**に警告バナーを出す。商談中に気づかず説明してしまうのを防ぐ。文面は「表示速度を計測できませんでした」のように、何が取れなかったかを明示する。

## 6. 必須の表示事項

- 「**トップページを診断した結果です**」をヘッダーとPDFの双方に明示する
- 各スコア項目に実測値を根拠として併記する
- 診断日時を表示する

## 7. 操作

- キーワードは結果画面で追加・削除・再診断ができる
- 共有URLのコピーとPDFダウンロードは、結果画面の上部と末尾の2箇所に置く
- キーボード操作でフォーカスが見えること
- `prefers-reduced-motion` を尊重する
