# SEO・LLMO 簡易診断ツール 要件定義書（v1）

| 項目 | 内容 |
|---|---|
| 文書バージョン | 1.0 |
| 作成日 | 2026年8月5日 |
| 対象システム | 営業担当向け Web診断ツール（社内利用） |
| 対象リリース | v1 |

---

## 1. 目的と背景

### 1.1 目的

営業担当が商談前・商談中にプロスペクトのサイトURLを入力するだけで、その場で説得力のある診断結果を提示できるツールを構築する。

### 1.2 設計上の前提

**プロスペクト側の協力を一切必要としない。** Google Search Console・Google Analytics との連携は行わず、公開情報のみで診断を完結させる。これにより「まず連携をお願いします」という商談上のハードルを排除する。

### 1.3 対象サイト

- 中小企業のコーポレートサイト・サービスサイト
- 大規模メディア、ECサイトは対象外（評価軸が異なるため）

---

## 2. スコープ

### 2.1 v1（本要件定義の対象）

| 機能 | 内容 |
|---|---|
| 診断範囲 | **入力URLの1ページのみ**（通常はトップページ） |
| 所要時間 | **約90秒**（60〜120秒） |
| 主要キーワードの順位取得 | PC / スマホ / 両方の選択制 |
| AI Overview の表示有無・引用判定 | 対応 |
| スコア判定 | 3カテゴリ100点満点（2026-08-19：権威性・被リンクを廃止） |
| 競合比較 | 上位3社を自動抽出して比較 |
| 改善アドバイス | 自動生成 |
| 結果の共有 | 共有URL・PDFダウンロード |
| 診断履歴 | ドメイン単位で保存 |

### 2.2 v2以降（本要件定義の対象外）

- 複数ページ診断（サービスページ等5〜10ページ、所要3〜6分）
- 事前バッチ診断モード
- AI可視性チェック（ChatGPT / Gemini / Perplexity での言及監視）
- 前回診断との差分表示

**v1を先にリリースする理由**：実際の商談で使ってみないと、どの機能が本当に必要か判断できないため。v1の利用実績をもとにv2の仕様を決める。

---

## 3. 利用フロー

```
1. 営業担当がGoogleアカウントでログイン
        ↓
2. URLを入力 ＋ デバイス（PC/スマホ/両方）を選択 → 「診断する」
        ↓
3. 進捗レールが6工程をリアルタイム表示（約90秒）
        ↓
4. 結果画面
   ├─ 改善アドバイス（最上部・顧客への提案としてそのまま提示可能）
   ├─ 総合スコア＋カテゴリ別スコア
   ├─ キーワード別 順位表（PC/スマホ・AI Overview）
   ├─ 競合比較
   └─ 改善インパクトの大きい項目 上位3件
        ↓
5. 共有URL または PDF を顧客に渡す
```

## 4. 機能要件

### 4.1 入力

| 項目 | 仕様 |
|---|---|
| URL入力欄 | 必須。スキーム省略時は `https://` を自動補完 |
| デバイス選択 | PC のみ / スマホのみ / 両方（既定：両方） |
| 地域設定 | 全国（Japan）固定 ※地域指定はv2で検討 |
| バリデーション | 形式不正時はその場でエラー表示 |

**UI方針**：1画面完結。入力欄と診断ボタンのみ。診断開始後は入力欄が上部バーに収納される。

### 4.2 キーワード推定

| 項目 | 仕様 |
|---|---|
| 抽出数 | 8個（環境変数で5〜10に調整可能） |
| 抽出元 | title / meta description / 見出し / 本文 |
| 使用API | Claude API（claude-sonnet-5） |
| 除外ルール | ブランド名単体は最大1つ、1語のビッグワードは最大2つ |
| 優先ルール | 「地域名＋サービス名」「サービス名＋比較/料金/おすすめ」等の商用意図のある語 |
| 手動編集 | **結果画面でキーワードの追加・削除・再診断が可能** |
| 失敗時 | title・見出しからの簡易抽出にフォールバックし、警告を表示 |

### 4.3 検索順位・AI Overview

| 項目 | 仕様 |
|---|---|
| 使用API | SerpApi |
| 取得範囲 | 上位20位まで。圏外は「20位圏外」と表示 |
| デバイス | 選択に応じて desktop / mobile |
| 地域 | gl=jp, hl=ja, location=Japan |
| AI Overview | 表示有無＋引用ドメインを取得。本文取得は既定オフ（追加課金のため） |
| 引用判定 | 自社ドメインの完全一致 |
| キャッシュ | 同一キーワード×デバイスを24時間保持 |

### 4.4 スコア判定

#### 4.4.1 基本方針

**スコアの数値はすべてルールベースで確定させる。Claude API は文章生成にのみ使用し、点数の判断には一切関与させない。**

理由：同じサイトを2回診断してスコアが変わると、営業ツールとして信用を失うため。同一入力からは必ず同一スコアが出ることを保証する。

#### 4.4.2 配点表

**総合100点＝（テクニカル30 ＋ コンテンツ30 ＋ LLMO 25）を100点換算**

2026-08-19：権威性・被リンクカテゴリ（旧15点）を廃止した。DataForSEO連携自体を停止し、
被リンクを診断・スコアに一切使わない方針（ユーザー判断）。

**① テクニカルSEO（30点）**

| 評価項目 | 配点 | 判定基準 |
|---|---|---|
| 表示速度（モバイル） | 40 | PageSpeed Insights スコアに比例 |
| 表示速度（PC） | 10 | 同上 |
| モバイル対応 | 15 | viewport メタタグの有無 |
| 構造化データ | 20 | JSON-LD の設置有無 |
| クロール可能性・HTTPS | 15 | noindex 8 / canonical 4 / HTTPS 3 |

**② コンテンツSEO（30点）**

| 評価項目 | 配点 | 判定基準 |
|---|---|---|
| 本文の情報量 | 30 | 2,500文字で満点（日本語のため文字数で評価） |
| キーワード網羅性 | 25 | 推定キーワードのページ内出現率 |
| タイトル・見出し構造 | 25 | title 20〜40字 8 / H1が1つ 6 / H2数 6 / description 5 |
| E-E-A-T要素 | 20 | 運営者情報・著者情報・連絡先・実績表記・許認可の検出数 |

**③ LLMO対応度（25点）**

| 評価項目 | 配点 | 判定基準 |
|---|---|---|
| FAQ / QA構造化データ | 25 | FAQPage / QAPage / HowTo の有無 |
| Q&A形式の見出し | 20 | 疑問形・解説形の見出し数（5個で満点） |
| 冒頭の定義文 | 20 | 冒頭段落が40〜200文字（引用されやすい長さ） |
| リスト・表による整理 | 15 | ul/ol/table の数（6個で満点） |
| AI Overview での引用 | 20 | 表示されたキーワードのうち自社が引用された割合 |

※ AI Overview が1件も表示されないキーワード群だった場合は、減点対象とせず中立評価（50%）とする。

#### 4.4.3 閾値の運用

**本文2,500文字などの満点ラインは暫定値。** 運用開始後に実際の診断結果を10〜20件確認して調整する。

閾値はソースコード1ファイル（`scoring.py`）に集約し、調整時に他へ影響が出ない構造とする。

#### 4.4.4 表示

- 総合スコアと3カテゴリスコアを視覚的に提示（数値の羅列を避ける）
- 各項目について「現状の実測値」を根拠として併記
- 80以上／60以上／40以上／それ未満の4段階で色分け

### 4.5 競合比較

| 項目 | 仕様 |
|---|---|
| 抽出社数 | 3社 |
| 選定ルール | 自社より上位に表示された回数が多い順 |
| **除外対象** | **ポータルサイト・比較サイト** |
| 比較指標 | 文字数 / H2数 / Q&A見出し数 / FAQスキーマ / 構造化データ種類数 / リスト・表数 / 内部リンク数 / E-E-A-T要素数 |
| 解説文 | Claude API が数値差分のみを根拠に自然文を生成 |

**除外リストの初期値**：食べログ、ホットペッパー、エキテン、ぐるなび、Wikipedia、Amazon、楽天市場、Yahoo!ショッピング、求人媒体各社、まとめ系メディア

除外リストは**管理画面から追加・削除できる**こと。業種によって邪魔になるドメインが変わるため。

**解説文の制約**：与えられた数値以外を書かない。推測で数値を作らない。商談でそのまま読み上げられる文体とする。

### 4.6 被リンク分析（廃止）

2026-08-19：DataForSEO Backlinks連携・権威性カテゴリを廃止した（ユーザー判断）。
本節は欠番とし、旧仕様は残さない。

### 4.7 改善アドバイス

| 項目 | 仕様 |
|---|---|
| 配置 | 結果画面の最上部 |
| 分量 | 4〜5文・300字以内 |
| 構成 | 現状（総合スコアと強み）→ 課題2つ（数値根拠つき）→ 最初に着手すべきこと1つ |
| トーン | **煽らない。** 事実と改善余地を淡々と示す |
| 制約 | 与えられた数値以外を書かない。根拠のない断定をしない |
| 対象読者・文体 | 専門用語を避け、サイト運営者・担当者への改善アドバイスとして「〜を改善しましょう」のように次の行動が分かる文章にする（2026-08-19：営業トーク要約から改善アドバイスに変更） |

### 4.8 出力・共有

| 機能 | 仕様 |
|---|---|
| 共有URL | `/report/{診断ID}`。認証必須 |
| PDFダウンロード | Playwright による印刷レンダリング。A4 |
| PDF掲載範囲 | 要約・スコア・順位表・競合比較の全項目 |
| 明記事項 | **「トップページを診断した結果です」を画面・PDF双方に明示** |

診断範囲を明記することで、「サイト全体のスコア」という誤解を避ける。

### 4.9 診断履歴

- 全診断をドメイン単位で保存（実行者・日時・スコア・結果全体）
- 一覧画面から過去の結果を再表示可能
- 再訪問時の前回比較表示は v2 で実装

## 5. 非機能要件

### 5.1 性能

| 項目 | 目標値 |
|---|---|
| 1診断の所要時間 | 90秒（最大120秒） |
| 同時実行 | 10名が同時に診断しても劣化しないこと |

**工程別の想定所要時間**

| 工程 | 秒数 |
|---|---|
| ① サイトを読み込み中 | 6〜8 |
| ② 対策キーワードを推定中 | 5〜10 |
| ③ 検索順位とAI Overviewを取得中 | 20〜30 |
| ④ 表示速度を計測中 | 30〜45 |
| ⑤ 競合サイトを分析中 | 10〜15 |
| ⑥ スコア算出・解説とアドバイスを生成中 | 20〜30 |

③④は並行実行するため、支配項は④（PageSpeed Insights の実測時間、短縮不可）。

2026-08-19：被リンク調査工程を廃止し、6工程構成に変更した。

### 5.2 待ち時間のUX

**商談中に無言で90秒待たせない**ことを最重要とする。

- 診断はジョブとして非同期実行し、進捗を Server-Sent Events でリアルタイム配信
- 6工程の進捗レールを表示し、完了した工程には実測値を添える（例：「モバイル 62／100」）
- タイムアウトによる画面停止を起こさないこと

### 5.3 部分成功（重要）

**どの工程が失敗しても診断全体を止めない。**

- 取得できた項目だけで結果を組み立てる
- 失敗した工程は画面に警告として明示する
- サイト本体のクロール失敗のみ、続行不能としてエラー表示

理由：商談中にAPIエラーで画面が真っ白になるのが最悪の事態であるため。

### 5.4 コスト制御

| 項目 | 設定 |
|---|---|
| 1日の診断上限 | 30件／人（環境変数で変更可） |
| SERPキャッシュ | 24時間 |
| クロールキャッシュ | 6時間 |
| PageSpeedキャッシュ | 12時間 |
| SERP同時実行数 | 4 |

### 5.5 クロールのマナー

競合サイトを取得するため、以下を遵守する。

- robots.txt の尊重
- User-Agent の明示（連絡先URLを含む）
- 同一ドメインへの同時アクセス数制限（3並列）
- タイムアウト設定（25秒）

## 6. 認証・権限

| 項目 | 仕様 |
|---|---|
| 認証方式 | **Google OAuth 2.0** |
| 許可範囲 | 自社ドメインのGoogleアカウントに限定（`hd` パラメータ＋許可リスト） |
| セッション | HttpOnly / Secure クッキー |
| 記録 | 診断ごとに実行者アカウントを保存 |
| 想定利用者数 | 10名 |

**個人単位の認証とする理由**：誰がいつどのサイトを診断したかを記録でき、レート制限も人単位でかけられるため。共有IDのBasic認証ではこれができない。

## 7. システム構成

### 7.1 構成図

```
[ブラウザ] ──Google OAuth──> [FastAPI]
     └────SSE（進捗）─────>    ├─ ジョブ管理
                                ├─ Playwright（自社・競合のクロール）
                                ├─ SerpApi（順位・AI Overview）
                                ├─ PageSpeed Insights API（表示速度）
                                ├─ Claude API（キーワード推定・解説・改善アドバイス）
                                └─ SQLite（履歴・キャッシュ）
```

2026-08-19：DataForSEO Backlinks連携を廃止した。

### 7.2 技術スタック

| 層 | 採用技術 |
|---|---|
| バックエンド | Python 3.13 / FastAPI |
| 非同期処理 | asyncio（プロセス内ジョブ管理） |
| クロール | Playwright（Chromium）／ httpx + BeautifulSoup をフォールバック |
| フロントエンド | サーバーサイドテンプレート＋素のJavaScript（ビルド工程なし） |
| データベース | SQLite |
| コンテナ | Docker |

**フロントにReact等を使わない理由**：1画面完結の社内ツールであり、ビルド工程を持つ利点が薄いため。保守を単純にする。

### 7.3 デプロイ

| 項目 | 仕様 |
|---|---|
| 実行環境 | Google Cloud Run |
| インスタンス | 最小1・最大1（ジョブ状態をプロセス内に保持するため） |
| スペック | 2 vCPU / 2GB（Playwright のため） |
| ストレージ | Cloud Storage への SQLite バックアップ（日次） |

**各PCへのローカル配布としない理由**：APIキーが人数分に分散し、キャッシュも共有できず、履歴も残らないため。

**将来の拡張**：利用者が増えて1インスタンスで足りなくなった場合は、ジョブ管理を Redis + RQ に置き換え、SQLite を Cloud SQL に移行する。この2箇所以外は変更不要な構造とする。

**すべて自社契約。診断される側の契約・協力は一切不要。**

### 8.1 想定コスト（月額）

1診断あたりのSERPリクエスト数＝約12（キーワード8個 × 平均1.5デバイス）

| 利用ペース | 月間診断数 | SERPリクエスト | SerpApiプラン |
|---|---|---|---|
| 控えめ（1件/人日） | 200件 | 2,400 | Developer $75 |
| 標準（2件/人日） | 400件 | 4,800 | **Production $150 を推奨** |
| 多め（4件/人日） | 800件 | 9,600 | Production $150 |

**Developer プラン（5,000件）は「標準」ペースで枠の96%に達し、月末に枠切れとなるリスクがある。** SerpApi は枠を使い切ると早期更新（プラン料金の再支払い）となるため、商談当日の停止を避ける観点から Production プランを推奨する。

その他：Claude API は1診断あたり数円、Cloud Run が月$30〜40程度。

※ 料金は変動するため、契約前に各社の料金ページで最新を確認すること。

## 9. データ設計

### 9.1 テーブル

**users**
| カラム | 内容 |
|---|---|
| email | Googleアカウント（主キー） |
| name | 表示名 |

**audits**
| カラム | 内容 |
|---|---|

| カラム | 内容 |

| カラム | 内容 |
